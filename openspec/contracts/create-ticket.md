# MCP Tool Contract: `create_ticket`

## Overview

Creates a support ticket for an authenticated resident. Also used for human escalation (with `category: "escalation"`). Used by the [Incident Management](../capabilities/incident-management.md) capability.

| Property | Value |
|----------|-------|
| **Auth** | `resident` — requires valid JWT with `okta_sub` (Phase 2+) |
| **Idempotent** | Yes — `idempotency_key` = SHA256(session_id + turn_index), 1-hour window |
| **Phase 1 Backend** | MongoDB `mock_cases` (no auth gate) |
| **Phase 2 Backend** | MongoDB `mock_cases` (auth gate enforced) |
| **Phase 3 Backend** | Salesforce REST API (Case object) |

These fields are injected by the orchestrator, not provided by the LLM:

| Field | Type | Description |

## Error Taxonomy

| Error Code | Description | Retryable | When |
|-----------|-------------|:---------:|------|
| `AUTH_REQUIRED` | No JWT present. User must authenticate. | No | Anonymous user attempts ticket creation (Phase 2+) |
| `AUTH_INSUFFICIENT_SCOPE` | JWT present but missing required claims (`property_id`) | No | Malformed or incomplete JWT |
| `VALIDATION_ERROR` | Invalid input (missing required fields, invalid enum) | No | Bad request |
| `DUPLICATE_DETECTED` | `idempotency_key` already exists within 1-hour window | No | Returns original ticket instead of creating duplicate |
| `DATABASE_UNAVAILABLE` | MongoDB connection failure | Yes | Infrastructure issue |
| `SALESFORCE_UNAVAILABLE` | Salesforce REST API unreachable (Phase 3 only) | Yes | Salesforce outage |
| `RATE_LIMITED` | Internal rate limiting triggered | Yes | High traffic |

### Duplicate Detection Response

When `DUPLICATE_DETECTED`, the error includes the original ticket:

```json
{
  "error": {
    "code": "DUPLICATE_DETECTED",
    "message": "A ticket with this idempotency key already exists",
    "retryable": false,
    "details": {
      "original_case_id": "MOCK-001",
      "original_case_number": "CS-10042",
      "original_created_at": "2026-08-03T12:00:00Z"
    }
  }
}
```

## Idempotency

| Property | Value |
|----------|-------|
| **Key** | `idempotency_key` = SHA256(session_id + turn_index) |
| **Window** | 1 hour from first request |
| **Behaviour** | If key exists within window, return original ticket (no new creation) |
| **Storage** | `idempotency_key` stored as unique index on `mock_cases` (Phase 1–2) or checked via Salesforce external ID (Phase 3) |

## Auth Enforcement

| Phase | Auth Gate | Behaviour |
|-------|-----------|-----------|
| Phase 1 | **Not enforced** | All users are anonymous. Ticket creation works without JWT. |
| Phase 2 | **Enforced** | MCP tool router checks for valid JWT. Anonymous users receive `AUTH_REQUIRED`. |
| Phase 3 | **Enforced** | Same as Phase 2 |

Enforcement is always in the MCP tool router, never in prompt instructions (Architectural Invariant #2).

## Phase-Specific Backend

| Phase | Backend | Details |
|-------|---------|---------|
| Phase 1 | MongoDB `mock_cases` | Insert document into `mock_cases` collection. No auth gate. |
| Phase 2 | MongoDB `mock_cases` | Same collection, auth gate enforced. |
| Phase 3 | Salesforce REST API | `POST /services/data/vXX.0/sobjects/Case` with OAuth 2.0 Client Credentials. Idempotency via Salesforce external ID field. |
